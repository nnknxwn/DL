# A. Public Leaderboard

## Anomaly Detection Contest: Поиск аномалий в табличных данных

В рамках этого контеста вам предстоит решить задачу обнаружения аномальных состояний оборудования / транзакций на основе показаний датчиков.

## Описание датасета

Данные представляют собой табличный датасет с независимыми объектами (строками):

- **`train.csv`**:
  - `id` — уникальный идентификатор объекта (не является признаком).
  - `sensor_0` ... `sensor_5` — анонимизированные числовые признаки (показания датчиков).
  - `anomaly` — целевая переменная:
    - `0` — нормальное состояние;
    - `1` — аномалия.
- **`test.csv`**:
  - `id` — уникальный идентификатор объекта.
  - `sensor_0` ... `sensor_5` — показания датчиков для предсказания.
- **`sample_submission.csv`**:
  - `id` — идентификатор объекта из `test.csv`.
  - `anomaly_score` — непрерывный скор аномальности (чем выше значение, тем выше вероятность/степень аномальности).

## Метрика качества

- **Основная метрика: Average Precision** — площадь под Precision-Recall кривой (`average_precision_score` в `scikit-learn`).
- **Требование к сабмиту:** в колонку `anomaly_score` необходимо отправлять **непрерывный скор** (вероятность класса 1 или Reconstruction Error).

## Ограничения по архитектурам и методам

- **Запрещено использовать градиентный бустинг** (`CatBoost`, `XGBoost`, `LightGBM` и т.д.) и классический Machine Learning (`RandomForest`, `IsolationForest`, `SVM` и др.).
- **Разрешено использовать только нейросетевые архитектуры, разобранные в обучающем ноутбуке и их вариации:**
  1. **Многослойный перцептрон.**
  2. **Автоэнкодеры.**

*Вы можете экспериментировать с гиперпараметрами и элементами архитектур из ноутбука:*

- Количество и размер скрытых слоёв;
- Функции активации (ReLU, LeakyReLU, GELU и др.);
- Регуляризация (`Dropout`, L2-регуляризация / `weight_decay`);
- Нормализация (`BatchNorm1d`);
- Алгоритмы оптимизации, learning rate, размер батча и кол-во эпох.

## Финальная сдача и оценивание

В B и C используется **последняя принятая (OK) посылка до дедлайна**. Ошибочные и отправленные после дедлайна посылки не заменяют предыдущую принятую. Лучший A автоматически финальным не становится. B/C дают 0 технических баллов. До дедлайна B не раскрывает Public/Private AP; C проверяет структуру Jupyter notebook v4 с code cells, не выполняет его. Без принятого до дедлайна ноутбука нельзя получить баллы за приватную часть.

Public AP последней принятой B < 0.2 либо отсутствие принятой B до дедлайна дают итог 0. При Public AP >= 0.2 начисляются 50 public points, рассчитывается Private AP и баллы за место в лидерборде. Итог будет опубликован после дедлайна.

## Сдача после дедлайна

После дедлайна можно получить только 50/100 баллов за преодоление бейзлайна.

Разрешены только предоставленные данные и указанные выше нейросетевые методы.

# B. Final Submission

## B. Final Submission — последняя принятая посылка до дедлайна

Загрузите `submission.csv`.

Разрешено **100 посылок за весь контест**. Ошибочные посылки тоже расходуют попытку.

Для итогового оценивания используется **последняя принятая (OK) посылка B до дедлайна**, даже если она хуже предыдущей. Лучший результат A её не заменяет. Ошибочные и отправленные после дедлайна посылки не заменяют предыдущую принятую. Если принятой B до дедлайна нет, итог — 0. Проверьте итоговый вердикт и сохраните локальную копию выбранного файла.

Формат: до 1 MiB, колонки строго `id,anomaly_score`, все test ID ровно по одному. Score — конечное вещественное число: больше означает более аномальный объект. Отрицательные scores и >1 допустимы; NaN/inf, пропуски, нечисловые значения, повторные/лишние/пропущенные ID недопустимы. До дедлайна только проверка формата, OK/0. Public/Private AP не раскрываются.

После дедлайна значение Public AP < 0.2 даёт итог 0. При Public AP >= 0.2 — 50 баллов и до 50 баллов от места в лидерборде на приватной части. Если до дедлайна в задаче C нет сданного ноутбука, баллы за приватную часть получить нельзя.
