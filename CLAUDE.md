# DL — домашние задания по курсу Deep Learning (вуз)

Репозиторий для домашних заданий по глубокому обучению. Задания сдаются через Яндекс Контест.
Часть исходных материалов курса (лекции, прошлые ноутбуки) отсутствует — опираться на то, что лежит в репо.

## Структура

Каждое задание — отдельная папка `dl_hwN_*/`:

- `README.md` — условие задания, перенесённое из Яндекс Контеста (с исходной разметкой: заголовки, списки).
- выданные данные и учебные материалы (csv, учебный ноутбук) — как получены, не редактировать.
- решения (ноутбуки, скрипты, сабмиты) — в той же папке, в подпапке `solution/` (создаётся при начале работы).

### Уроки ДЗ 1 (пригодятся в следующих контестах)

- Public в маленьком контесте очень шумный (≈40 позитивов → ±0.06 AP): выбирать модель по повторной CV, не гнаться за public. Топ public — максимум из тысяч попыток, он завышен.
- Если CV и public расходятся — сначала проверить гипотезы (сдвиг признаков через adversarial validation, утечка через дубли/соседей, новые типы аномалий через пробу AE), а не перебирать модели вслепую.
- Финальные модели обучать на всём train с числом эпох из CV — небольшой, но надёжный прирост.
- Свежий взгляд (агент без контекста) и `critic` перед финалом окупаются: ловят дыры в плане и подтверждают воспроизводимость.

### Уроки ДЗ 2

- Если val насыщен (все хорошие варианты дают 1.000) — сравнивать по log-loss и по кросс-валидации на train+val (почти-дубли в одном фолде), а не по val accuracy.
- Искать почти-дубли (корреляция уменьшенных картинок) между и внутри сплитов: они завышают val и дают метрику без меток — согласованность предсказаний на парах почти-дублей test. Именно она нашла ошибку 02 (двойники с разными классами).
- Псевдо-лейблинг (если разрешён) проверять честно: в CV метки неразмеченным даёт модель, не видевшая этот фолд. Ручная правка меток test и подбор через public запрещены — чинить модель.
- На MPS `channels_last` в 3 раза медленнее; fp16 не ускоряет. Аугментации считать батчем на устройстве (affine_grid), DataLoader workers не нужны.
- Ноутбук с долгим обучением выполнять с `--ExecutePreprocessor.timeout=-1` и из его штатной папки (относительный `DATA_DIR`); выполненный ноутбук не перезаписывать генератором.

## Правила, общие для заданий

- Использовать **только** методы, разрешённые в условии (обычно — архитектуры из учебного ноутбука курса). Бустинг и классический ML запрещены, если условие не говорит иное.
- Никаких внешних данных, pretrained-весов и данных из интернета.
- Финальный ноутбук для сдачи — валидный Jupyter notebook v4, без лишних outputs; в нём: подготовка данных, обучение, локальная валидационная метрика, экспорт сабмита.
- Перед отправкой сабмита — проверить формат локально (все id из test ровно по разу, нет NaN/inf, нужные колонки). Число посылок ограничено.
- Фиксировать seed для воспроизводимости.

## Окружение

- Python 3.12, PyTorch, pandas, numpy, scikit-learn (scikit-learn — только для препроцессинга, сплитов и метрик).
- venv в корне репо: `.venv` (в .gitignore). Создание: `uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python torch numpy pandas scikit-learn matplotlib jupyter ipykernel nbformat nbconvert`.
- Системный `python3` (3.9) без pandas — всегда запускать `.venv/bin/python`. В VS Code выбрать интерпретатор `.venv/bin/python`, иначе Pyright ругается на импорты.
- `multiprocessing` на macOS запускать только из `.py`-файла, не через stdin/heredoc (`python - <<EOF`): воркеры не стартуют и бесконечно перезапускаются.

## Порядок работы над заданием-контестом

Папка `dl_hwN_*/solution/` (на примере ДЗ 1):

| Файл | Назначение |
|---|---|
| `build_solution.py` | генератор `solution.ipynb` через nbformat (ноутбук правится **здесь**, а не руками) |
| `solution.ipynb` | чистовик для сдачи (задача C); автономный, сам пишет `submission.csv` |
| `experiments.py` | рабочая копия: формат `# %%` (в VS Code открывается как ноутбук); `python experiments.py <группа>...` гоняет группы конфигов параллельно |
| `runs/results.jsonl` | итоги всех экспериментов (в git); `runs/*.npy` — OOF/test предсказания (не в git) |
| `EXPERIMENTS.md` | журнал: эксперименты, диагностика, все посылки с sha256 и вердиктами |
| `check_submission.py` | проверка формата CSV перед любой посылкой |
| `submissions/` | архив каждого отправленного файла (CSV и копия ноутбука) |

Команды (из папки `solution/`):
```bash
../../.venv/bin/python build_solution.py solution.ipynb   # перезаписывает ноутбук без outputs! для пересборки после прогона — другое имя
../../.venv/bin/jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 solution.ipynb   # -1: финальная ячейка может обучаться часами
../../.venv/bin/python check_submission.py submission.csv
../../.venv/bin/python experiments.py <группа> [<группа> ...]
```

Правила сдачи (Яндекс Контест, задачи A/B/C):
- A показывает Public AP, но не идёт в зачёт; B засчитывается (последняя OK), AP до дедлайна не показывает; C — ноутбук.
- В B отправлять **только тот файл, что уже проверен в A** (совпадение sha256). C — ноутбук, который воспроизводит этот CSV.
- Страховка: рабочие B и C отправить как можно раньше, потом перезаписывать.
- Каждую посылку — копией в `submissions/` и строкой в `EXPERIMENTS.md`; ноутбук тоже архивировать перед перезаписью.
- Выбор модели — по локальной CV (повторная StratifiedGroupKFold), public — только sanity-check: он маленький и шумный.
