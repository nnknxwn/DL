# A. Public Leaderboard

## Image Classification Contest: Классификация изображений

В рамках этого контеста вам предстоит построить свёрточную нейронную сеть, которая по изображению определяет его класс. Всего классов 5, они скрыты под нейтральными именами `class_0`, ..., `class_4`.

## Описание датасета

Данные находятся в архиве `dl_hw2_competition_data_v5.zip` во вложении «Скачать условие задачи». Внутри папки `mri_classification_dataset/`:

- **train/** — 1390 обучающих изображений в подпапках `class_0` ... `class_4`. Название подпапки задаёт класс изображения.
- **val/** — 298 изображений с той же структурой. Используйте их для локальной оценки качества, сравнения экспериментов и выбора модели.
- **test/** — 300 изображений без меток. Для них необходимо сделать предсказания.
- **sample_submission.csv** — пример файла с колонками `id,label`.

Изображения имеют размер 256×256 или 512×512. Соответствие классов фиксировано: `class_0 → 0`, `class_1 → 1`, `class_2 → 2`, `class_3 → 3`, `class_4 → 4`. В архиве также находится обучающий ноутбук `image_classification_tutorial.ipynb`.

## Метрика качества

- Основная метрика: **Accuracy** — доля изображений, для которых класс предсказан правильно.
- В колонку `label` необходимо отправлять **целый номер класса от 0 до 4**.
- Тестовая выборка разделена на скрытые части Public и Private. Во время соревнования отображается качество только на Public.

## Ограничения по архитектурам и методам

Разрешены **свёрточные нейронные сети (CNN), обученные с нуля**, и только предоставленные данные. Архитектуру нужно реализовать самостоятельно из базовых слоёв, например `torch.nn.Conv2d`, `Linear`, слоёв активации, пулинга и нормализации. Готовые реализации сетей из `torchvision.models`, `timm` и аналогичных библиотек запрещены, в том числе без предобученных весов (`weights=None`, `pretrained=False`).

Вы можете экспериментировать с архитектурой и процессом обучения:

- количеством свёрточных слоёв, каналов, размерами ядер и skip connections;
- функциями активации, пулингом и нормализацией;
- регуляризацией: `Dropout`, `weight_decay` и аугментациями;
- оптимизаторами, learning rate, размером батча и количеством эпох;
- TTA, ансамблями и **псевдо-лейблингом** на выданных test-изображениях.

Варианты сравнивайте по validation. Если после выбора конфигурации обучаете финальную модель на train+val, опишите этот шаг в ноутбуке; качество на этих данных уже не является независимой validation-оценкой.

## Уровень бейзлайна

Порог для получения положительной оценки — **Public Accuracy ≥ 0.85** у финальной посылки B. Ровно 0.85 проходит порог. Это целевой уровень качества, которого нужно добиться самостоятельными экспериментами с данными соревнования.

## Формат сабмита

Файл `submission.csv` должен содержать две колонки:

```
id,label
img_00001,2
img_00002,0
img_00003,4
```

`id` — имя файла из `test/` без расширения. Каждый из 300 ID из `sample_submission.csv` должен встретиться ровно один раз; порядок строк любой. `label` — целое число от 0 до 4, записанное без дробной части. Формат UTF-8, размер до 1 MiB. Пропуски, повторы ID, NaN/inf и лишние колонки не допускаются.

## A. Public Leaderboard

Public Accuracy = баллы A / 100: например, 85 баллов означают Accuracy = 0.85. В монитор идёт лучший результат. Любой корректный CSV получает OK, в том числе ниже бейзлайна; OK подтверждает формат файла.

Разрешены **20 посылок за весь контест**. Ошибочные посылки тоже расходуют попытку.

## Финальная сдача и оценивание

В **B** загрузите выбранный финальный CSV. Лучший результат A автоматически финальным не становится. В **C** загрузите ноутбук решения `solution.ipynb`. Для B и C отдельно учитывается **последняя принятая посылка до дедлайна**. Более поздняя ошибочная посылка не отменяет ранее принятую. Ошибочные посылки расходуют попытки. Принятый до дедлайна ноутбук обязателен для ненулевой оценки за приватную часть.

B/C дают 0 технических баллов. До дедлайна B проверяет только формат и не раскрывает Public/Private Accuracy; C проверяет структуру notebook, не выполняя код.

Public Accuracy финальной B < 0.85 либо отсутствие корректной своевременной B дают итог 0. При Public Accuracy ≥ 0.85 начисляются **50 баллов** и ещё **от 0 до 50 баллов за место по Private Accuracy** среди прошедших порог.

Итог будет опубликован после дедлайна.

Сроки указаны на странице соревнования. Сдавайте B и C заранее, оставляя время на исправление файлов. Поздние и непринятые файлы не учитываются.

## Правила честной работы

Запрещены внешние обучающие данные, предобученные модели/веса, поиск исходных test-изображений и их меток в интернете, ручная разметка test и обмен predictions/submissions между участниками.

Обычные ML-библиотеки, документация и собственные псевдо-метки разрешены. Преподаватель может проверить воспроизводимость и соблюдение правил по ноутбуку; нарушения могут привести к аннулированию работы.

# B. Final Submission

## B. Final Submission

Загрузите выбранный `submission.csv`. Для B разрешены **100 попыток**.

Ошибочные посылки тоже расходуют попытку. Финальной считается **последняя принятая посылка B до дедлайна**; более поздняя ошибочная посылка не отменяет ранее принятую. Лучший результат A не заменяет финальную посылку B. Сохраните локальную копию выбранного CSV и соответствующие веса модели.

Формат такой же, как в A: UTF-8, до 1 MiB, колонки `id,label`. Все 300 test ID должны встретиться ровно один раз, `label` — целое число от 0 до 4. До дедлайна проверяется только формат, балл B равен 0. Public/Private Accuracy не раскрываются.

Загрузите финальный CSV и notebook до дедлайна, оставляя время на исправления. Поздние и непринятые файлы не учитываются.
